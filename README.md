# FastAPI template

A compact, production-minded starting point for asynchronous FastAPI services.
It includes PostgreSQL, SQLAlchemy, Alembic migrations, a protected SQLAdmin
panel, validated environment settings, health checks, tests, CI, and a
non-root Docker image.

This repository is infrastructure and an example domain, not a complete
application. Replace or protect the sample `/api/v1/users` routes according to
your authorization model before storing real user data.

## Stack

- Python 3.13 and [uv](https://docs.astral.sh/uv/)
- FastAPI and Pydantic Settings
- asynchronous SQLAlchemy with asyncpg
- PostgreSQL and Alembic
- SQLAdmin
- pytest, Ruff, and Pyright
- Docker Compose and GitHub Actions

## Included production safeguards

- secrets and deployment-specific values come from environment variables;
- passwords are hashed with Argon2 and never returned by the API;
- admin login uses configured credentials and a signed session;
- database sessions roll back on errors and the connection pool is disposed
  during graceful shutdown;
- readiness checks PostgreSQL, while liveness remains independent of external
  services;
- CORS and trusted hosts are configurable;
- API docs are disabled when `APP_ENV=production`;
- the container runs as an unprivileged user and CI actions are pinned to
  immutable commit SHAs.

## Quick start with Docker

Requirements: Docker with Compose.

```bash
cp .env.example .env
openssl rand -hex 32
```

Put the generated value in `SECRET_KEY`, replace `ADMIN_PASSWORD`, and add a
database password to `.env`:

```dotenv
POSTGRES_PASSWORD=replace-with-a-random-database-password
```

Then migrate and start the service:

```bash
docker compose run --rm app alembic upgrade head
docker compose up --build
```

The API is available at <http://localhost:8000>, OpenAPI documentation at
<http://localhost:8000/docs>, and the admin panel at
<http://localhost:8000/admin>.

Stop the stack with `docker compose down`. Add `--volumes` only when you also
intend to delete the local PostgreSQL data.

## Local development

Requirements: Python 3.13, uv, and a running PostgreSQL instance.

```bash
cp .env.example .env
uv sync --dev
uv run alembic upgrade head
uv run fastapi dev main.py
```

Useful commands:

```bash
make format     # format and apply safe lint fixes
make check      # lint, format-check, type-check, and test
make migrate    # apply all database migrations
```

Create a migration after changing models:

```bash
uv run alembic revision --autogenerate -m "describe the change"
uv run alembic upgrade head
```

Review every autogenerated migration before applying it.

## Configuration

Pydantic validates configuration at startup and fails fast when required
secrets are missing or too short.

| Variable | Purpose | Default |
| --- | --- | --- |
| `APP_NAME` | OpenAPI and admin title | `FastAPI Template` |
| `APP_ENV` | `development`, `test`, or `production` | `development` |
| `DEBUG` | FastAPI debug responses | `false` |
| `LOG_LEVEL` | Application log level | `INFO` |
| `API_PREFIX` | Prefix for versioned API routes | `/api/v1` |
| `DATABASE_URL` | SQLAlchemy async PostgreSQL URL | local PostgreSQL |
| `DATABASE_ECHO` | SQL query logging | `false` |
| `SECRET_KEY` | Session-signing secret, at least 32 characters | required |
| `ADMIN_ENABLED` | Enable SQLAdmin | `true` |
| `ADMIN_USERNAME` | SQLAdmin login | required |
| `ADMIN_PASSWORD` | SQLAdmin password, at least 12 characters | required |
| `CORS_ORIGINS` | JSON array of allowed browser origins | `[]` |
| `ALLOWED_HOSTS` | JSON array for host-header validation | `["*"]` |

For example:

```dotenv
CORS_ORIGINS=["https://app.example.com"]
ALLOWED_HOSTS=["api.example.com"]
```

## Endpoints

- `GET /health/live` — process liveness; does not contact PostgreSQL
- `GET /health/ready` — readiness; returns `503` when PostgreSQL is unavailable
- `GET /api/v1/users?offset=0&limit=100` — paginated example listing
- `POST /api/v1/users` — example user creation with Argon2 password hashing
- `/admin` — authenticated SQLAdmin interface when enabled

## Project layout

```text
core/
├── admin/                 SQLAdmin authentication, views, and assets
├── api/                   app factory, dependencies, and routers
├── orm/                   engine, models, and Alembic migrations
├── schemas/               request and response models
├── services/              place for application use cases
├── settings/              validated environment configuration
└── utils/                 reusable helpers
tests/                     automated tests
main.py                    ASGI entry point
```

Keep routers thin as the project grows: put business operations in `services`,
database queries in a repository/data-access layer, and external integrations
behind explicit clients.

## Production checklist

Before deploying a real service:

1. Set `APP_ENV=production`, strong unique secrets, exact `ALLOWED_HOSTS`, and
   only the required `CORS_ORIGINS`.
2. Disable the admin panel if it is not needed. Otherwise restrict it at the
   network or reverse-proxy level in addition to its login.
3. Add application-specific authentication and authorization to private API
   routes. The sample user listing is intentionally not an auth framework.
4. Terminate TLS at a trusted load balancer or reverse proxy and only trust
   forwarded headers from that proxy.
5. Run `alembic upgrade head` once as a release step before starting replicas;
   do not let every replica race to migrate the schema.
6. Configure PostgreSQL backups, restore tests, monitoring, alerting, and log
   collection in the deployment platform.
7. Tune worker/replica count, pool sizes, timeouts, and resource limits from
   measured traffic rather than template defaults.
8. Keep `uv.lock` committed and require the CI workflow before merging.
